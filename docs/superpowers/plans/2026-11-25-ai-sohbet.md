# AI Chat in the Notch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A chat panel in the notch, opened by a global shortcut or a control-center button, that talks to Gemini, Claude or ChatGPT with the user's own API key, streams answers, renders Markdown, accepts dropped files and keeps a local history.

**Architecture:** All network calls and key handling live in a new Rust module (`ai_chat.rs`): it reads the key from Windows Credential Manager, builds the provider's request, streams Server-Sent Events and emits text deltas to the notch window. The frontend never sees a key; it sends the conversation and file paths and renders events. Chat is a new notch mode (`'chat'`) with its own component, a pure history/Markdown module, and a new Settings tab.

**Tech Stack:** Rust (tauri 2.11, reqwest 0.12 `chunk()` streaming, keyring, base64, serde_json), React 19 + TypeScript, bun selfcheck scripts.

**Spec:** `docs/superpowers/specs/2026-11-23-coucou-ozellikleri-design.md`, section 2.

## Global Constraints

- API keys live only in Windows Credential Manager: keyring service `"Cyexs AI"`, username = provider id (`gemini`, `anthropic`, `openai`). Never in settings, localStorage, logs, error text, events or settings export. The frontend can only ask "is there a key".
- Requests go only to the chosen provider's official host: `generativelanguage.googleapis.com`, `api.anthropic.com`, `api.openai.com`. No telemetry.
- A file is sent only when the user sends a message with it attached. History keeps file names, never contents.
- No new npm or cargo dependencies. reqwest streams with `Response::chunk()` (no `stream` feature needed).
- Default provider `gemini`. Default shortcut `Ctrl+Alt+Space`.
- Default models (constants in `ai_chat.rs`, one place to update): Gemini `gemini-3.8-flash`, Claude `claude-haiku-5-5`, OpenAI `gpt-6-luna`. Before writing Task 1, the implementer opens the provider model pages and confirms each id still exists; if one is retired, use the provider's listed cheap replacement and note it in the commit message.
- Limits: at most 5 files per message, 10 MB per image/PDF, 200 KB per text file (truncated with a note above that), 30 chats kept in history (oldest dropped).
- UI language follows the app (`useT`, `src/locales/*.json`); tr and en written by hand, ar/de/es/fr translated. The model answers in the user's language (system prompt says so).
- User-visible name is "CyexsDock"; internal keys keep the `nectar-` prefix (`nectar-chat-provider`, `nectar-chat-hotkey`).
- Every Rust build on this machine needs Kaspersky protection paused by the user (see memory gotchas); TS-only checks do not.

## Review Focus

1. **Key leak through an error.** A provider error, a reqwest error or a panic message must never contain the key. Covered by `redact_key` tests in Task 1 and by Task 2 mapping every error through it.
2. **Wrong or revoked key, no internet, rate limit (HTTP 429).** The user sees a short, readable message in the chat bubble ("Anahtar geçersiz", "İnternet yok", "Çok fazla istek, biraz bekleyin"), not raw JSON. Covered by `friendly_error` tests in Task 1.
3. **A stream that stops halfway** (connection drop, user presses Stop, chat closed with Esc). The partial answer stays visible and marked as cut off; the next message still works. Covered by the cancel test in Task 2 and the `finishMessage(..., "cut")` check in Task 4.
4. **Unsupported, huge or unreadable dropped file** (a `.exe`, a 40 MB video, a locked file). It is refused with a message before anything is sent. Covered by `classify_file` tests in Task 2.
5. **Shortcut already taken by another app.** Registration fails quietly at startup; Settings shows the warning and the control-center button still opens chat. Covered by Task 3's `chat_hotkey_ok` and Task 6's warning row.

### Task 1: Provider requests, stream parsing and error text (pure Rust)

**Files:**
- Create: `src-tauri/src/ai_chat.rs` (this task: the pure part only)
- Modify: `src-tauri/src/main.rs` (add `mod ai_chat;`)

**Interfaces:**
- Produces:
  - `#[derive(Clone, Copy, Debug, PartialEq, serde::Deserialize, serde::Serialize)] #[serde(rename_all = "lowercase")] pub enum Provider { Gemini, Anthropic, Openai }` with `fn id(self) -> &'static str`, `fn model(self) -> &'static str`
  - `#[derive(Deserialize)] pub struct ChatTurn { pub role: String /* "user" | "assistant" */, pub text: String }`
  - `pub struct Part { pub mime: String, pub name: String, pub kind: PartKind }`, `pub enum PartKind { Text(String), Base64(String) }` (images and PDFs are `Base64`)
  - `pub fn build_request(p: Provider, key: &str, history: &[ChatTurn], parts: &[Part]) -> (String /* url */, Vec<(&'static str, String)> /* headers */, serde_json::Value /* body */)` — `parts` attach to the last user turn.
  - `pub fn parse_sse_line(p: Provider, line: &str) -> Option<String>` — returns the text delta in one `data:` line, `None` for anything else.
  - `pub fn redact_key(text: &str, key: &str) -> String` — replaces every occurrence of `key` (and keys shorter than 8 chars are not searched) with `***`.
  - `pub fn friendly_error(status: u16, body: &str) -> String` — Turkish/English-neutral code string the frontend translates: `"key"` for 400 with "API key"/401/403, `"rate"` for 429, `"model"` for 404, `"server"` for 5xx, else `"other:<first 200 chars of the provider's error.message>"`.
  - `pub const SYSTEM_PROMPT: &str = "You are a helpful assistant inside CyexsDock, a Windows desktop app. Answer in the language the user writes in. Be concise; use Markdown for lists and code.";`

Request shapes (verify against current provider docs while coding):
- Gemini: `POST https://generativelanguage.googleapis.com/v1beta/models/{model}:streamGenerateContent?alt=sse`, header `x-goog-api-key`. Body `{systemInstruction:{parts:[{text}]}, contents:[{role:"user"|"model", parts:[{text}|{inline_data:{mime_type,data}}]}]}`. Delta: `candidates[0].content.parts[*].text`.
- Anthropic: `POST https://api.anthropic.com/v1/messages`, headers `x-api-key`, `anthropic-version: 2023-06-01`. Body `{model, max_tokens: 4096, stream: true, system, messages:[{role, content:[{type:"text",text} | {type:"image",source:{type:"base64",media_type,data}} | {type:"document",source:{type:"base64",media_type:"application/pdf",data}}]}]}`. Delta: `type == "content_block_delta"` → `delta.text`.
- OpenAI: `POST https://api.openai.com/v1/responses`, header `Authorization: Bearer`. Body `{model, stream: true, instructions, input:[{role, content:[{type:"input_text"|"output_text",text} | {type:"input_image",image_url:"data:<mime>;base64,<data>"} | {type:"input_file",filename,file_data:"data:application/pdf;base64,<data>"}]}]}` (assistant turns use `output_text`). Delta: `type == "response.output_text.delta"` → `delta`.
- Text-file parts are sent as a text block `"[<name>]\n<content>"` for all providers.

### Task 2: Keys, file reading, streaming commands

**Files:**
- Modify: `src-tauri/src/ai_chat.rs`, `src-tauri/src/main.rs` (register commands)

**Interfaces:**
- Consumes: Task 1.
- Produces (tauri commands, all `async` except where noted):
  - `chat_key_status() -> HashMap<String, bool>` — `{gemini, anthropic, openai}` → key present.
  - `chat_set_key(provider: Provider, key: String) -> Result<(), String>` — trims; empty deletes the entry.
  - `chat_test_key(provider: Provider) -> Result<(), String>` — GET the provider's model list (`/v1beta/models`, `/v1/models`, `/v1/models`) with the stored key; error is a `friendly_error` code.
  - `chat_send(window: Window, id: String, provider: Provider, history: Vec<ChatTurn>, files: Vec<String>) -> Result<(), String>` — reads files, streams, emits to the calling window: `chat-delta {id, text}`, then exactly one of `chat-done {id}`, `chat-error {id, code}`, `chat-cut {id}` (cancelled). Returns `Err(code)` only for problems before the request (no key → `"nokey"`, file refused → `"file:<reason>:<name>"`).
  - `chat_cancel(id: String)` (sync) — sets a cancel flag the stream loop checks between chunks.
  - `pub fn classify_file(path: &Path, len: u64) -> Result<(String /* mime */, bool /* is_text */), String /* reason: "type" | "size" */>` — by extension: png/jpg/jpeg/webp/gif → image, pdf → `application/pdf`, txt/md/csv/json/log/xml/html/css/js/ts/tsx/py/rs/java/c/cpp/cs/go/sh/ps1/yaml/yml/toml/ini → text; anything else `"type"`; image/PDF over 10 MB → `"size"`. Text over 200 KB is read truncated to 200 KB with `"\n[... truncated]"`.
- Keyring: `keyring::Entry::new("Cyexs AI", provider.id())`, same pattern as `caldav.rs:21`.
- Every error string that leaves this module goes through `redact_key`. Nothing in this module logs request bodies or headers; `diagnostics::log` may log only `chat: <provider> status <code>`.
- HTTP: one shared `reqwest::Client` with 20 s connect timeout and no total timeout; read with `resp.chunk().await`, split on `\n`, keep a partial-line buffer across chunks, feed each line to `parse_sse_line`.

- Behaviour (from the spec's decisions):
  - `chat-hotkey` or the control-center button: set mode `'chat'`, expand the notch, call `set_window_keyboard_focus {enabled: true}`, focus the input. Pressing the hotkey while chat is open closes it.
  - While mode is `'chat'`, `onHoverEnd` does nothing. `Esc` or a click outside the notch closes it: mode back to the normal target mode, `set_window_keyboard_focus {enabled: false}`. The current chat stays in state and storage; reopening shows it.
  - Size: 460 × 420 px panel. Header: provider name, "Yeni sohbet", history dropdown (titles, delete per item, "Tümünü sil"), close. Body: messages via `renderMarkdown`, copy button per assistant message, auto-scroll while streaming. Footer: attached file chips (removable), textarea (Enter sends, Shift+Enter newline), Send/Stop button.
  - No key for the chosen provider: the body shows a short message and an "Ayarları aç" button that opens Settings on the AI tab (`open_settings` with tab `"ai"`, same mechanism as `calendar-sync`).
  - Sending: `addUserMessage` → `invoke("chat_send", {id, provider, history: historyForApi(chat), files})`; deltas through `appendDelta`; `chat-done/cut/error` through `finishMessage`. Errors show the translated code (`chat.err.key`, `chat.err.rate`, …) inside the bubble. Stop → `chat_cancel`. Closing the panel while streaming keeps streaming in the background.
  - Provider changes mid-chat: next message goes to the new provider (read `nectar-chat-provider` at send time).
- Drop zone: `shelf.rs` `Drop` adds `"x"`/`"y"` (client physical pixels from `client_point`) to the `shelf-drag-drop` payload. While a file drag is over the notch, the shelf panel shows a second zone "Soru sor" on its right. On drop, if the point (divided by `devicePixelRatio`) is inside the "Soru sor" zone's rect, the paths go to chat (`pendingFiles`, mode `'chat'`) instead of the shelf; otherwise the shelf behaves exactly as today. Text drops (no paths) always go to the shelf.
